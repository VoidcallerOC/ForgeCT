## Risk assessment

| Question                                                                 | Finding                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Does removing the root site change Vercel's detected framework or build? | No. Root Directory is `nitro` and the framework is pinned to `nitro` on the project; the build log shows the Nitro build. Vercel clones the whole repository, so a repo-root `.vercelignore` would matter (commit 49a6d03 removed one that broke the build), but no such file is added here.                                                                                                                   |
| Apex → www redirect and query-string preservation?                       | Unchanged: generated by `nitro/vite.config.ts`, verified live before this change.                                                                                                                                                                                                                                                                                                                              |
| Do GitHub workflows expect root files?                                   | `quality.yml` "Validate site" ran root `npm test` (Prettier, html-validate, link check, image budget, API tests) and root Playwright. After the archive it runs Prettier and the API tests; the two browser steps are removed. The job name is unchanged, so the required check keeps its name. `production-smoke-schedule.yml` and the main-branch smoke job use `scripts/smoke-production.mjs`, which stays. |
| Does rollback remain practical?                                          | Yes, on both axes that matter. Deployment rollback is Vercel's instant rollback to a previous READY deployment and does not involve the repository. Code rollback is `git revert` of the merge, which restores every file. Re-serving the static site was already a re-platform (Root Directory would have to change) before this change; the archive keeps that option in the tree.                           |
| Any route or asset regression?                                           | None possible from this change: production never served root files, and `nitro/public` carries its own copies of every public asset (identical bytes for images, favicon, brand, robots; newer sitemap and route manifest).                                                                                                                                                                                    |
| Does the Nitro SEO-parity check still work?                              | Yes: `certifiedRoot` now points at `archive/certified-static-site`, and `npm run check` passes with "SEO parity with the certified site".                                                                                                                                                                                                                                                                      |
